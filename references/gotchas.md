# 踩坑与实战退路（Ego Lite 版）

汇总四个创作者后台的真实暗坑与 Ego Lite 操作边界，按“会不会让你白干或传错稿”排序。每条均来自真实后台实测（2026-09 至 2026-11-19）。

---

## 一、B 站登录会话「假在线」导致封面白做

**现象**：进入 B 站投稿页 `member.bilibili.com/platform/upload/video/frame` 后页面可正常加载，甚至能传视频、打开封面编辑器并填好 4:3 和 16:9 双图，但在点击封面「完成」或「存草稿」时静默失败或无法保存。追查 `api.bilibili.com/x/web-interface/nav` 才发现返回 `code=-101`、`isLogin=false`（会话已过期）。

**修法**：在刚打开 B 站页面时、投递大文件或制作封面**之前**，优先核对账号昵称/头像真实可见，并通过 `page.fetch("https://api.bilibili.com/x/web-interface/nav", { credentials: "include" })` 确认 `data.isLogin === true`（注意：在 `member.bilibili.com` 调跨子域 `api.bilibili.com` 时**必须传 `{ credentials: "include" }`**，否则默认不带 Cookie 会把已登录态误报成 `-101`）。若未登录或会话过期，立即 `await task.handOff()` 交给 Jack 扫码登录后再继续。

## 二、微信视频号在上传期间全表单锁定，且后台标签页读不出视频时长

| 平台 | 上传/处理期间表单可编辑？ |
|---|---|
| 小红书 | ✅ 标题 / 话题 / 声明 / 封面 可预填 |
| 抖音 | ✅ 标题 / 声明 可预填 |
| B站 | ✅ 标题 / 标签 / 分区 / 声明 可预填 |
| **微信视频号** | ❌ **锁定**：「文件上传中，请等待完成后再编辑」 |

**两大实测坑**：
1. **必须等上传与转码全部完成、字段解锁后**，才能填写视频描述、话题、位置、原创和封面。
2. 当视频号编辑页长期处于非当前激活标签（`document.visibilityState === 'hidden'`）时，页面内视频元素可能维持 `readyState === 0` 且 `duration` 为空/`NaN`，卡在「本地待读取」。需短切激活一次该页（`page.evaluate` 不可靠唤醒时切到前台观察），读出与 `ffprobe` 一致的时长和分辨率后再等平台处理回执。
3. **操作期静音、交接前还原**：视频号（及小红书、抖音）上传/复开后可能自动有声播放视频预览，打扰作者。进页及每次恢复/复开后，应立即遍历主文档及 `wujie-app` shadow root 将 `<video>` 和 `<audio>` 设成 `muted = true` 并调用 `pause()`，**切勿把 `volume` 改为 `0`**；全部验收完毕、准备 `finish({ keep })` 交接给用户前，保持媒体暂停（监听或防止意外自动播放）并把 `muted` 还原为 `false`，以免用户接手后手动点预览却听不到声音。
4. **横屏设第二张封面弹「使用此素材作为封面？」**：视频号横屏稿设好个人主页 3:4 封面后，点击分享卡片 4:3「编辑」可能先浮出「使用此素材作为封面？」提示，**必须点「直接编辑」真正进入分享卡片弹窗后再传 4:3 图**，否则文件选不进目标卡。

## 三、B 站封面的双面板与同步陷阱

B 站封面编辑器包含 **#editor_4_3（首页推荐）** 和 **#editor_16_9（个人空间）** 两个独立面板，常见三个坑：
1. **进入弹窗干扰**：新版封面编辑器有时先弹出「智能生成封面」引导，需先点「不使用」才能手动传图。
2. **未切对面板导致覆盖错槽**：`active` 类在 `#editor_4_3` / `#editor_16_9` 的**父元素**上，不在自己身上，且不能用 `/active/.test(...)`（会误中 `inactive`）。上传前必须按空格切分父元素 `className` token 验证 `active`！
3. **保存时弹窗提议同步**：点「完成」可能弹出「检测到个人空间封面（16:9）未修改。是否将「4:3封面」的改动同步到「16:9封面」？」。**必须选「不同步，手动编辑」**，点同步会把 4:3 覆盖到 16:9 槽位上。

## 四、B 站「仅话题」词在标签框静默消失 & 自动塞无关标签

1. **自动无关标签占坑 & SVG 不可直接 `.click()`**：平台会根据文件名或内容自动往标签栏里塞默认词（如「记录」「原创」）。必须在加标签前先清理无关标签；注意 `<svg>` 元素没有 DOM `.click()` 方法（直接调会抛 `TypeError`），应先 `scrollIntoView` 再用 `page.mouse.click` 点击关闭图标坐标。**切勿在空输入框里按 Backspace**，B 站会删掉最后一个已保存的标签！
2. **「仅话题」词静默吞掉与「参与话题」活动绑定风险**：有些词在 B 站只以「话题」形态存在，直接在标签框回车会被静默清空且无任何提示。**注意：B 站「参与话题」常与官方征稿/主题活动直接绑定，严禁未经 Jack 明确提起就擅自走「参与话题 → 搜索更多话题」去把稿件挂上活动！** 遇到回车被吞的词，直接留作明确待办报给 Jack，绝不悄悄换词也绝不擅自挂活动；只有 Jack 明确点名要参与某个活动/话题时才走「参与话题」入口。
3. **未抽帧前的封面空槽**：视频刚上传尚未生成默认抽帧图时，`.cover-content` 里还没有「更改封面」文字按钮，而是空槽 `.cover-empty-pill` / `.cover-slot`，直接点它即可打开双封面编辑器。
4. **内部滚动容器与创作声明收起误触**：B 站投稿页有内部滚动容器，操作分区、标签、声明或存草稿前先 `scrollIntoView({ block: 'center' })`；选创作声明时直接 DOM 精准点击目标 `.bcc-option`，防止收起下拉时误切到「含虚构演绎内容」。

## 五、隐藏的 `<input type="file">` 与动态文件选择器

四个平台的文件输入框大都是隐藏的（`0×0` / `opacity: 0` / `display: none`）：
- 在 Ego Lite 中，若页面已有稳定的 `<input type="file">`（如小红书 `input.upload-input` 或视频卡片内部），`page.setInputFiles()` 可直接设置，但必须核对命中了当前视频/当前封面卡片对应框（例如 B 站页内同时有字幕 `.txt` 框和旧版 `1×1` 框，不能盲选）。
- 若页面通过点击投放区动态触发选择器或存在多重嵌套，必须**先**建立 `const chooserPromise = page.waitForFileChooser({ timeout: 10_000 })`，**再**点击可见投放区 `ref`，然后 `await chooser.setFiles(absPath)`。注意切勿先点击后等待，否则事件已错过会超时卡死。

## 六、微信视频号「保存草稿」不保存视频标注 & `wujie` Shadow DOM

1. **草稿丢标注**：实测点击视频号「保存草稿」并从草稿箱复开同一条稿时，短标题与描述在，但「视频标注」必定回退到占位符「选择视频标注」。因此必须走：**先保存草稿 → 另开标签进草稿箱复核 → 回到原编辑页最后设置「视频标注」→ 读回按钮确认后不再点保存、直接留页交接**。
2. **`wujie-app` shadow root 与隐藏弹窗陷阱**：视频号发布表单嵌套在 `wujie-app` 的 shadow DOM 里，直接在顶级 `document` 运行 `querySelector` 往往只能读到外层导航栏。写 `page.evaluate()` 探测字段或 `File` realm 时需先进入 `document.querySelector('wujie-app')?.shadowRoot`。此外，页内常驻隐藏的 `.weui-desktop-dialog`（如「将此次编辑保留?」和隐藏「确定」按钮）：声明原创必须只取 `getBoundingClientRect().height > 80` 的可见弹窗；封面弹窗确认必须**严格匹配文本等于 `"确认"` 的可见橙色主按钮**（不可写成 `=== "确认" || === "确定"`）。
3. **草稿箱直达路径与前台渲染**：草稿箱真实路径为 `https://channels.weixin.qq.com/platform/post/draftListManager`（不是 `/platform/post/draft`）；新开临时页查草稿箱前须 `bringToFront` 并用 `waitForFunction` 等 `wujie-app` 渲染出目标条目。
4. **位置搜选精确 POI（绝不写死默认地标）**：点击 `.post-position-wrap .position-display` 后默认仅列出本机定位附近地点；仅当作者本次确认需添加具体地点时，在 `.location-filter-wrap input[placeholder*="搜索附近位置"]` 输入关键词并点击 `.weui-desktop-search__btn`。搜索结果前排常出现同前缀商铺或停车场（如某地标便利店、地上停车场），**必须严格按 `.option-item .name` 精确相等选中**，切勿模糊包含匹配，选后回读 `.post-position-wrap .location-name` 核验。未指定地点时则选首项「不显示位置」。

## 七、小红书话题面板竞态、悬浮发布条遮挡、定时开关误触与大视频退路

1. **悬浮发布条 `<xhs-publish-btn>` 遮挡与正文未聚焦**：小红书底部悬浮的 `<xhs-publish-btn>` 常拦截 `div.tiptap.ProseMirror` 中下部点击；且填完标题不先聚焦正文就直接点「话题」，会把话题敲进标题框撑超 `20` 字。应先将 `ProseMirror` 滚到视口中央、点击其上部坐标聚焦后再点 `button.contentBtn.topic-btn`。
2. **原创开关误触定时发布**：`.custom-switch-card .d-switch` 同时匹配「原创声明」与「定时发布」两个开关，**必须限定 `.original-wrapper .d-switch`**，避免意外打开定时发布。
3. **话题建议面板竞态**：面板返回有延迟且会异步重渲染。若先读取旧位置再点，很容易错点成同前缀词。每次输入关键词等待面板就绪后，必须**重新运行 `page.snapshot()` 获取最新 `ref` 或在 `.tippy-box .item` 匹配精确名称后点击**，随后在 `div.tiptap.ProseMirror a.tiptap-topic` 核对名称。
4. **横封面进编辑器默认仍选 3:4 裁剪框**：上传 4:3 横封面到小红书「设置封面」弹窗时，弹窗默认仍选中左侧「3:4」裁剪比例。**必须点击左侧「裁剪 → 4:3」切换为横版比例框并目视确认未裁掉两侧文字，再点「完成」**。
5. **大视频封面编辑器报错**：遇到「视频加载遇到问题」时，直接点击页面官方退路**「回退到旧版封面编辑弹窗」**，然后上传相应方向封面并确认。
6. **「内容类型声明」没有“无需声明”选项**：当成片不含 AI 生成素材也无其他需声明项时，**留空不选**（保持占位符「添加内容类型声明」）即代表无需声明。
7. **本地草稿上限**：小红书视频笔记草稿存储在**当前浏览器本地**（上限约 100 条），同一浏览器同一账号内可见；已满时不可擅自删除旧稿，需请 Jack 决策。复开同名多条草稿时按完整标题 + 最新 `保存于` 时间戳挑选顶部条目。
8. **10-bit HEVC + 24-bit PCM `.mov` 原片优先、失败再走兜底（2026-11-21 实测更新）**：小红书**默认先按正常流程直接上传原片**（2026-11-21 实测 61.58 MB 达芬奇导出 `10-bit HEVC Main 10 / yuv420p10le + pcm_s24le .mov` 可一次秒传并通过画质评估，零画质损耗），**切勿提前预防性转码**。仅在较大体积 `.mov` 实测导致小红书网页端 renderer 长时间无响应或上传永久停在 `0%`（同一时间图片接口正常 200）时，才向 Jack 说明并征得同意，仅为小红书用硬件编码（如 `h264_videotoolbox -b:v 12M -pix_fmt yuv420p -c:a aac -b:a 256k -movflags +faststart`）生成标准 8-bit H.264 + AAC MP4 并通过 `job.xhs.videoPath` 兜底上传（其余平台继续保持原片不动）。
9. **加话题触发「关联活动」自动勾选（2026-11-20 实测）**：在小红书正文里添加普通话题（如 `#独立开发`）时，即使脚本未点击页面下方的「关联活动」，平台也可能因话题命中官方活动而**自动关联活动**（例如「独立开发者 · 报上Demo...」卡片按钮自动变成红色「取消关联」）。选话题时应优先避开下拉中带活动标注的候选项；选完所有话题后及复开验收时，必须检查「关联活动」区块，只要 Jack 未明确提起要求参与该活动，一律点击「取消关联」解除绑定并复核无残留。
10. **封面验收排除 `coverDetectTag` 角标干扰（2026-11-21 实测）**：小红书复开草稿页的封面检测角标 `img.coverDetectTag`（`216×66`, `ratio=3.273`）和推荐卡片 `ai-cover-preview-card` 会出现在 `img.cover` 前面。回读真实封面尺寸时必须排除 `coverDetectTag` / `ai-cover-preview-card` / `activity-cover`，精准匹配主封面 `img.cover`（`naturalWidth >= 400`）。
11. **未传完硬点「暂存离开」静默丢视频、补传重置原创开关、话题默认推荐抢跑（2026-11-28 实测）**：① 100MB+ 大视频五平台并发上传时易超 25 秒，若不等到明确上传完成信号（「重新上传 / 检测为高清视频」）就点「暂存离开」，小红书依然返回「保存成功」，但复开后视频丢失（「暂未上传视频」「拖拽或点击上传」），且只靠 `!stillUploading` 会误报绿灯；② 在已有草稿页补传视频后，平台会自动将「原创声明」开关重置为关闭，补传后必须复查并重新勾选；③ 搜「人工智能」等短词时，默认热门推荐里可能原本就含模糊包含项（如 `#人工智障与人工智能`），等待面板刷新必须按「首行名称精确匹配或前缀匹配」判定，不能用宽松 `includes` 抢跑。

## 八、抖音动态 `ref`、弹窗拦截、切封面弹窗与「继续编辑」单入口覆盖风险

1. **`#添加话题` 按钮 `ref` 会漂移且下拉混有活动词**：每添加一个话题后组件会重绘，下一轮必须重新快照获取新的 `ref` 或使用 `text="#添加话题"`，避免词条被当成普通文本写入而不变成 `[data-mention="#"]` 实体。下拉候选中常混有带「活动」「任务」「激励」等标记的词条，应优先选普通纯话题实体，且绝不点击「添加活动 / 任务」挂载区（除非 Jack 明确提起）。
2. **双封面弹窗指针拦截与横屏独立单槽弹窗**：不要误向页面外层的隐藏 input 传图。注意**竖屏视频**打开封面弹窗时通常同时显示「设置竖封面 / 设置横封面」双 Tab，而**横屏视频**在编辑页有「横封面4:3」与「竖封面3:4」两张独立 `.coverControl-CjlzqC` 卡片，点进单张卡片时弹窗可能只显示当前槽位（无切换另一方向的 Tab）。脚本与人工均应先检测弹窗是否同时含双 Tab：若无，须分别点进两张独立卡片各自上传并点「完成」，复开后核对横封 `ratio >= 1.15`、竖封 `ratio <= 0.9` 防止误覆盖。
3. **「继续编辑」风险**：抖音上传页仅弹出最近一次未发布视频的「是否继续编辑？」。复开前或点击后，必须立刻核对**标题与播放器时长**，确认是本条才操作；若发现已有别人的未发布草稿，先保留并报告 Jack，切勿覆盖。
4. **未传完点「暂存离开」静默丢视频 & 区分视频上传与发文助手检测（2026-11-28 实测）**：① 100MB+ 成片在未上传完成前点击「暂存离开」，抖音同样允许存稿并出现「继续编辑」，但复开后右侧退回「点击上传 或直接将视频文件拖入此区域」、`vids` 为空（标题、话题与双封面看似完好极易造成假绿灯）；Pass 1 必须等到云端流（`video-cn.douyin.com`）或有效 `<video>` + 「重新上传」出现后再暂存，Pass 2 必须正向强校验 `vids` 时长非空且无空上传提示；② 视频传完后右下角「发文助手 快速检测」还会从 `1%` 跑到 `99%`，监控上传进度时切勿把检测百分比误判成仍在上传而卡死。

## 九、Ego Lite 多会话与跨重启 `spaceId` 漂移

1. **`spaceId` 并非永久固定**：Ego Lite 重启或空间重整后，原有空间的数字 ID 可能变化（实测曾出现进度文件记 `spaceId: 9`，重启后对应空间变为 `id: 4`）。续做时必须用 `listTaskSpaces()` 按 `spaceId` **结合 `name` / `taskId`** 双重核对，并在各平台页面核对标题、片长和保存时间。
2. **禁止擅自接管 `user` 空间**：按 `ego-browser` 指南，检测到 `ownership: "user"` 的已有同名空间时，须先经用户同意才可 `claimTaskSpace(id)`。
3. **交接清理页签**：草稿复核常会多开草稿箱列表页、视频预览页等中间页签。交接前核对 `await task.tabs()`，只把每平台最终编辑页的 `label` 传入 `await task.finish({ keep: handoffLabels })`，其余中间页不要保留。
4. **Ego Lite 内核标签页硬静音（`0.6.3.17` 实测根因与永久规避）**：
   - **根因**：Ego Lite 在 `createTaskSpace`（初始 `p1`）与 `task.newPage()` 底层会硬编码调用 Chromium 内核的 `chrome::SetTabAudioMuted(wc, true, AUDIO_INDICATOR)`，且在 `finish()` / `handOff()` 移交用户后**不会自动解除**。网页 DOM 层的 `video.muted = false` 无法穿透浏览器进程级标签页静音，导致用户交接后播放任何平台视频都听不到声音。
   - **永久规避（已内置于 `runner.mjs` / `utils.mjs`）**：开新标签页时，把默认静音的 `p1` 仅作跳板，通过 `spawnUnmutedPage(task, launcherPage)`（加载 `data:text/html,<a id="ego-unmuted-spawn" href="about:blank" target="_blank">open</a>` 并配合 `waitForEvent("popup")` 点击弹出新页）生出**天生不带内核硬静音**的平台标签页，生完立即关闭跳板页。任务执行期仍靠 DOM `muteAndPausePage()` 静音防打扰，交接前 `restorePausedUnmuted()` 还原后用户点播放即可直接出声。
   - **手工开页 / 历史标签页兜底**：如果某页签（如手工 `task.newPage()` 开的 X 标签页）仍被 Ego Lite 内核静音，播放视频后**直接用鼠标左键单击标签页标题栏上带斜杠的 🔇 小喇叭图标本身**即可立刻解开；**切勿**走右键菜单「将网站静音 → 取消网站静音」（该菜单项对普通 `https://` 网页只改站点权限，不会清除 `AUDIO_INDICATOR` 标签级静音）。

## 十、X（Media Studio）自定义缩略图的实测暗坑（2026-11-20 实测）

1. **必须先点「更改缩略图」，再点「选择一帧或上传图片」里的「上传」链接**：直接找页面里的 `input[type="file"]` 极易命中媒体库右上角主上传框（`accept` 同时包含 `video/*` 和 `image/*`），结果会把封面图作为一条独立图片素材传进媒体库，根本不会绑定到视频上。正确路径永远是：`更改缩略图` → `waitForFileChooser` + 点 `a:text-is("上传")`。
2. **封面比例必须跟成片实际宽高比一致（2026-11-21 实测）**：X 播放器与信息流卡片随视频横竖屏自适应，切勿无脑默认传 16:9——**竖屏成片必须传 9:16 或 3:4 竖图，横屏成片传 16:9 横图**。
3. **大体积无损 PNG（> 2 MB）易卡顿或静默失败**：缩略图上传前优先转为 **≤ 1 MB 的同方向高清 JPG**（如 macOS `sips -s format jpeg -s formatOptions 90`），上传只需 2–4 秒即完成 `INIT → APPEND → FINALIZE (201) → edit.json (200)`。
4. **等待转圈落盘前切勿提前跳页**：点完上传后视频中央会出现加载转圈，必须等到 `edit.json` 返回 `200` 且出现「保存成功」提示（或 `get.json` 出现新 URL）再切走或点「帖子」，提前跳转会直接中断缩略图绑定。
5. **播放器仍显示视频帧 ≠ 封面没生效**：HTML5 `<video>` 一旦解码了第 0 帧或 `currentTime > 0`（如用户拖过进度条），页面上显示的永远是当前视频帧而不是 `poster` 属性。可靠验收方式是只读拉取 `/1/library/get.json?...&media_key=<mediaKey>`，确认返回的缩略图 URL 已从默认 `pbs.twimg.com/amplify_video_thumb/...` 变为自定义 `pbs.twimg.com/media/...` 并拉图抽检。
6. **在撰写弹窗内改封面绝不刷新页面**：若用户已在撰写弹窗里改写了推文内容并展开「编辑媒体设置」，必须直接在当前页操作 `更改缩略图 → 上传`，**严禁 `goto()` 或 `reload()`** 以免丢失用户的推文草稿。
7. **并发发帖与同名文件精准锁 `media_key`（2026-11-28 实测）**：若作者在等待转码间隙随手发了另一条新视频，或媒体库里存在历史同名文件（如多个 `v2.mov`），绝不可盲取 `/1/library/list.json` 第 0 条 `media_key` 或盲点第一个同名卡片；必须解析 `results` 并按 **`!tweeted` + `filename` + `duration`（匹配本地 `ffprobe` 时长）** 精准锁定本条 `media_key`，保存后回读 `/1/library/get.json` 校验时长、标题与自定义缩略图。

## 十一、原生图文模式的实测暗坑（2026-11-28 实测）

原生图文（`mode: "image"`）复用视频发布底座，但三平台网页端存在 6 个极易翻车的独有暗坑：

1. **抖音图文标题上限是 20 字符（不是视频的 30 字）**：超过 20 字符会被静默截断末尾文字。发多平台图文时，统一标题尽量控制在原始 ≤ 20 字，或在 `job.douyin.title` 单独提供 ≤ 20 字版本。
2. **微信视频号图文 `setInputFiles` 静默失效**：在 `finderNewLifeCreate` 的 `wujie-app` shadowRoot 中直接向 `ant-upload` 的隐藏 `<input type="file">` 调 `setInputFiles` 不会触发上传回调（`files` 为空、预览无图）。**必须先 `waitForFileChooser()` 再鼠标点击 `.ant-upload-drag-container`**，并在 `img.slider-img` 回读原图像素确认上传成功。
3. **微信视频号图文传完图会自动乱配不相关 BGM，且点歌名只是试听**：上传图片后系统会随机挂载一首默认背景音乐（曾实测给严肃科技内容配上用餐音乐）。必须显式打开 `.bgm-form-content-wrap` 外层 `.link-display-wrap` 搜纯音乐或选「不添加音乐」；且搜出结果后**点 `.song-info` 只会试听不会选中**，必须 hover 整行并点击该行右侧「选择」按钮，随后确认 `.link-list-options` 下拉浮层已收起，否则浮层会遮挡下方的「视频标注」和「保存草稿」按钮导致点击失效。
4. **微信视频号图文默认强带本机城市定位且无声明原创框**：进入 `finderNewLifeCreate` 时位置字段会自动填入当前定位城市，未要求带定位时必须主动切换为「不显示位置」；页面不含原创复选框，属于正常差异，记录「无此项」即可。草稿同样保存在 `draftListManager`，原页最后设置「视频标注」的交接顺序与视频完全一致。
5. **小红书图文新手指引吞正文 + closed shadow DOM 暂存按钮**：首次进入图文编辑页会弹出 `.feature-guide__btn`（「我知道了」），若未先关闭就点击正文框，聚焦会被浮层吞掉导致整段正文丢失（只剩后面通过按钮插入的话题）；此外 `<xhs-publish-btn>` 为 closed shadow DOM，`text="暂存离开"` 可能匹配不到，需走 `page.snapshot({ scope: "full_page" })` 取 `@ref` 点击。
6. **抖音图文正文一次性换行生星号 `*` + 音乐面板误选杂项原声**：向抖音图文编辑器一次性 `insertText` 含 `\n` 的多段文案，复开后行首可能出现多余 `*` 号，**必须逐行 `insertText` + `Enter`**；打开配乐必须点右侧 `.action-Q1y01k`（左侧「选择音乐」是纯标题），且抽屉内横向 Tab 易因滚动溢出点空误选推荐首行的奇怪原声，**直接用抽屉顶部的 `input[placeholder="搜索音乐"]` 搜纯音乐最稳**。
7. **视频与图文草稿箱物理隔离，可同日并行备稿**：实测小红书草稿箱分「视频笔记 / 图文笔记」双 Tab，抖音上传页分「未发布的视频 / 未发布的图文」双独立「继续编辑」槽位，微信视频号在 `draftListManager` 同列表并存，因此可安全并行准备同一主题的视频与图文置顶组合，互不覆盖。
